# MCP-сервер для доступа к API 1С:Напарник 0.2.0

Через этот сервер ИИ-агент в любом MCP-клиенте задаёт вопросы 1С:Напарнику, ИИ-ассистенту по разработке на платформе 1С:Предприятие. Написан на Go без сторонних библиотек и собирается в один exe.

Агент отправляет вопрос, сервер передаёт его в публичное API 1С:Напарника (`https://code.1c.ai`) и возвращает ответ целиком. Если указать каталог с выгрузкой конфигурации, 1С:Напарник сам находит и читает нужные модули. С отдельного разрешения он может создавать и править файлы.

## Возможности

- Вопрос 1С:Напарнику в новом или существующем диалоге, ответ возвращается полностью вместе с номером диалога для продолжения.
- Служебные команды: список диалогов, история, удаление, сжатие контекста, заполненность контекста, остаток лимитов.
- Чтение файлов проекта 1С:Напарником: список каталога, чтение с номерами строк, поиск файлов по имени и поиск текста с контекстом в стиле grep. Поиск параллельный, обходит junction.
- Запись файлов: создание и точечная правка. Кодировка и переводы строк сохраняются, новые `.bsl`, `.xml` и `.os` создаются в UTF-8 с BOM и CRLF, как в выгрузке 1С.
- Доступ к файлам задаёт только пользователь в настройках. Агент лишь включает чтение (`use_files`) или разрешает запись (`allow_write`) для конкретного вопроса. Каталоги записи должны лежать внутри каталогов чтения.
- После каждого вопроса агент видит, к каким файлам обращался 1С:Напарник и какие изменил.
- Все лимиты и таймауты меняются в `cfg.json`, все тексты для агента и 1С:Напарника в `tools.json`, без пересборки.

## Сборка

Нужен Go 1.27. В корне проекта:

```
build.cmd
```

Скрипт запускает `go vet` и тесты, затем собирает `BIN\naparnik-mcp.exe`.

## Подключение

Сервер подключается к любому MCP-клиенту как локальный (stdio): клиенту нужен путь к exe и переменные окружения. Ниже пример для Claude Code, в других клиентах настройка похожая.

Ключ берётся в личном кабинете 1С:Напарника, в разделе «Ключи доступа». Удобнее всего держать его в переменной окружения пользователя:

```
setx NAPARNIK_API_KEY "ваш ключ"
```

После этого перезапустите VS Code или терминал. Затем добавьте сервер в `.mcp.json` проекта:

```json
{
  "mcpServers": {
    "naparnik": {
      "command": "C:/путь/к/BIN/naparnik-mcp.exe",
      "env": {
        "NAPARNIK_API_KEY": "${NAPARNIK_API_KEY}",
        "NAPARNIK_FILES_ROOT": "C:/1CProjects/МойПроект/SRC",
        "NAPARNIK_WRITE_ROOT": "C:/1CProjects/МойПроект/SRC/Расширение"
      }
    }
  }
}
```

Можно и одной командой, тогда настройки сохранятся в `~/.claude.json` и в репозиторий не попадут:

```
claude mcp add naparnik -e NAPARNIK_API_KEY=... -e NAPARNIK_FILES_ROOT=C:/1CProjects/МойПроект/SRC -- C:/путь/к/BIN/naparnik-mcp.exe
```

Несколько каталогов перечисляются через `;`. Без `NAPARNIK_FILES_ROOT` 1С:Напарник файлов не видит, без `NAPARNIK_WRITE_ROOT` ничего не пишет.

## Настройки

| Переменная | Что задаёт |
|---|---|
| `NAPARNIK_API_KEY` | ключ API (обязательно) |
| `NAPARNIK_FILES_ROOT` | каталоги, которые 1С:Напарник может читать |
| `NAPARNIK_WRITE_ROOT` | каталоги, в которых он может создавать и править файлы |
| `NAPARNIK_BASE_URL` | адрес API, по умолчанию `https://code.1c.ai` |
| `NAPARNIK_CONFIG` | путь к `cfg.json`, по умолчанию рядом с exe |
| `NAPARNIK_TOOLS` | путь к `tools.json`, по умолчанию рядом с `cfg.json` или exe |

Переменные окружения важнее `cfg.json`. Если `NAPARNIK_CONFIG` или `NAPARNIK_TOOLS` указывает на несуществующий файл, сервер не запускается.

Каталоги проверяются при запуске. Несуществующий каталог пропускается, вложенный в другой каталог чтения отбрасывается как повтор. Каталог записи вне каталогов чтения игнорируется. Обо всём этом сервер пишет предупреждение в журнал.

### cfg.json

Числа и списки. В файле указывают только то, что меняется, остальное остаётся по умолчанию:

```json
{ "files": { "walk_timeout": "90s", "search_max_hits": 200 } }
```

Длительность пишется строкой: `"40s"`, `"15m"`, `"1h30m"`. Размер можно дать числом байт или строкой: `"80KB"`, `"32MB"`. Относительные пути в `files_root` и `write_root` считаются от каталога, где лежит `cfg.json`.

| Ключ | По умолчанию | Допустимо | Что задаёт |
|---|---|---|---|
| `api.base_url` | `https://code.1c.ai` | http(s)-адрес | адрес API |
| `api.api_prefix` | `/public/v1` | начинается с `/` | префикс путей API |
| `api.sse_max_line` | `16MB` | от 64KB | максимальная строка потока ответа |
| `files_root` | `[]` | список путей | каталоги чтения |
| `write_root` | `[]` | список путей | каталоги записи |
| `ask.timeout` | `15m` | от 1s | время одного вопроса целиком |
| `ask.max_tool_rounds` | `30` | 1–1000 | сколько раз за вопрос сервер отвечает на вызовы инструментов |
| `ask.file_log_show` | `30` | от 0 | сколько обращений к файлам показать агенту |
| `ask.default_language` | `1c` | непусто | язык программирования нового диалога |
| `timeouts.default` | `2m` | от 1s | время служебных инструментов |
| `timeouts.compact` | `10m` | от 1s | время сжатия контекста |
| `timeouts.extra` | `20s` | от 1s | название диалога, заполненность контекста, лимиты |
| `history.tool_result_chars` | `300` | от 1 | обрезка результатов инструментов в истории диалога |
| `files.list_page` | `200` | от 1 | элементов каталога за вызов |
| `files.read_default_lines` | `400` | до `read_max_lines` | строк файла по умолчанию |
| `files.read_max_lines` | `2000` | от 1 | максимум строк за вызов |
| `files.read_max_bytes` | `80KB` | от 1KB | максимум текста за вызов |
| `files.max_file_size` | `32MB` | от 1KB | файлы крупнее не читаются и не правятся |
| `files.find_max_hits` | `100` | от 1 | результатов поиска по имени |
| `files.walk_timeout` | `40s` | от 1s | время обхода каталогов при поиске |
| `files.walk_max_depth` | `40` | от 1 | глубина обхода |
| `files.workers` | `16` | 1–256 | параллельных чтений с диска |
| `files.search_max_hits` | `80` | от 1 | совпадений при поиске текста |
| `files.search_line_cut` | `200` | от 10 | символов строки в результате поиска |
| `files.search_file_size` | `8MB` | от 1KB | файлы крупнее при поиске пропускаются |
| `files.search_max_bytes` | `64KB` | от 1KB | объём результата поиска |
| `files.search_context` | `2` | до `search_max_context` | строк контекста по умолчанию |
| `files.search_max_context` | `10` | 0–100 | максимум строк контекста |
| `files.search_default_pattern` | `*.bsl` | шаблон имени | где ищется текст, если шаблон не задан |
| `files.write_max_bytes` | `1MB` | от 1KB | максимум содержимого за одну запись |
| `files.edit_context_lines` | `3` | 0–50 | строк вокруг правки в ответе 1С:Напарнику |
| `files.bom_crlf_extensions` | `.bsl`, `.xml`, `.os` | вида `.bsl` | новые файлы с BOM и CRLF |
| `mcp.max_message_bytes` | `64MB` | от 1MB | максимальное сообщение MCP |

### tools.json

Тексты: инструкция сервера для агента, сообщение об отсутствии ключа, заголовки и описания инструментов и их параметров. Полный набор вшит в exe, внешний файл содержит только изменённое:

```json
{ "agent": { "tools": { "naparnik_ask": { "title": "Спросить 1С:Напарника" } } } }
```

Файл делится на секции `agent` (что видит агент) и `naparnik` (что видит 1С:Напарник). В каждой есть `tools` с текстами инструментов и `fragments` с повторяющимися кусками. Текст можно записать строкой или массивом строк, массив склеивается через перевод строки.

В тексте `{имя}` заменяется значением. Значения берутся из настроек: `{read_dirs}`, `{write_dirs}`, `{default_language}`, `{read_default_lines}`, `{read_max_lines}`, `{search_context}`, `{search_max_context}`, `{search_default_pattern}`, `{bom_crlf_extensions}`. Кроме них можно подставить фрагмент своей секции. У двух фрагментов есть варианты, и вариант выбирает сервер. `files_access` бывает `none`, `read` или `read_write` в зависимости от того, заданы ли каталоги чтения и записи. `paths_note` бывает `one` или `many` по числу каталогов чтения. Пустой фрагмент просто исчезает из текста.

В `tools.json` меняются только тексты инструкции, сообщений, описаний инструментов и их параметров.

### Ошибки в файлах

Полный файл со всеми ключами и текущими значениями выводят `naparnik-mcp.exe -dump-config` и `naparnik-mcp.exe -dump-tools`, с него удобно начинать.

Сервер не запускается, если в файле неверный JSON, неизвестный ключ, значение вне диапазона, неизвестная подстановка или фрагменты ссылаются друг на друга по кругу. Причина с путём к ключу пишется в журнал, который виден в `/mcp`, например `files.worker: неизвестный ключ`.

## Инструменты

### Для агента

| Инструмент | Что делает |
|---|---|
| `naparnik_ask` | задаёт вопрос и возвращает ответ целиком |
| `naparnik_list_conversations` | список диалогов (`limit` 1–100, `offset`) |
| `naparnik_get_conversation` | история диалога по порядку |
| `naparnik_delete_conversation` | удаляет диалог безвозвратно |
| `naparnik_compact` | сжимает контекст длинного диалога, можно указать, что сохранить |
| `naparnik_context` | сколько токенов контекста занято |
| `naparnik_budget` | расход лимитов за 5 часов и за неделю |

У `naparnik_ask` такие параметры: `question`, `conversation_uuid` (продолжить диалог), `use_files` (по умолчанию true), `allow_write` (по умолчанию false), `programming_language`.

Без `conversation_uuid` создаётся новый диалог. Если ответ 1С:Напарника заканчивается вызовами инструментов, сервер выполняет свои, на серверные инструменты 1С:Напарника отвечает подтверждением и продолжает, пока не придёт ответ без вызовов или не наберётся `ask.max_tool_rounds` раундов. Агент получает текст ответа, журнал обращений к файлам, список изменённых файлов с полными путями, `conversation_uuid`, название нового диалога и заполненность контекста.

На ошибки API сервер добавляет подсказку: неверный ключ, исчерпан лимит (с текущим расходом), нет тарифа, диалог не найден, в диалоге уже идёт генерация, слишком много запросов.

### Для 1С:Напарника

1С:Напарник видит те же абсолютные пути, что агент и пользователь, с разделителем `/`. Относительный путь допускается, только если каталог чтения один. Выйти за каталоги чтения нельзя ни через `..`, ни через абсолютный путь.

| Инструмент | Что делает |
|---|---|
| `local_list_dir` | содержимое каталога с размерами файлов, отбор по подстроке и постраничный вывод; пустой путь показывает доступные каталоги |
| `local_read_file` | файл с номерами строк, частями; понимает UTF-8 с BOM и без, UTF-16 LE |
| `local_find_files` | поиск файлов и каталогов по имени: подстрока или шаблон с `*` и `?` |
| `local_search_text` | поиск подстроки без учёта регистра, вывод в стиле grep с контекстом и номерами строк |
| `local_edit_file` | замена точного фрагмента; фрагмент должен встречаться один раз, либо `replace_all` |
| `local_write_file` | создание файла или перезапись целиком, недостающие каталоги создаются |

Поиск идёт параллельно, заходит в junction и пропускает каталоги, имя которых начинается с точки. Если время обхода вышло или набран лимит совпадений, 1С:Напарник получает об этом пометку и совет сузить запрос.

`local_edit_file` и `local_write_file` появляются, только если агент передал `allow_write=true` и заданы каталоги записи. Писать нельзя в сам каталог записи и в пути с сегментом на точку (`.git` и подобные). Существующий файл сохраняет свой BOM и переводы строк. Запись атомарная: сначала временный файл рядом, потом переименование.

| Файл | Назначение |
|---|---|
| `build.cmd` | проверка, тесты и сборка |
| `SRC/main.go` | запуск и флаги |
| `SRC/mcp.go` | протокол MCP |
| `SRC/tools.go` | инструменты агента и цикл вопроса |
| `SRC/files.go`, `SRC/files_write.go` | доступ к файлам для 1С:Напарника |

| `SRC/texts.go`, `SRC/tools.json` | тексты и шаблоны описаний |
| `SRC/naparnik/` | клиент API 1С:Напарника и разбор потока ответа |

## Примечания

- Прочитанные файлы попадают в контекст диалога и расходуют лимит 1С:Напарника. Для общих вопросов без привязки к проекту выгоднее `use_files=false`.
- Резервных копий перед записью нет. Каталог записи лучше держать под git и смотреть `git diff` после правок.
- Поиск по всей выгрузке большой конфигурации может упереться в 40 секунд обхода. Тогда стоит сузить каталог в вопросе или увеличить `files.walk_timeout`.
- Ключ API в `cfg.json` не принимается, только через переменную окружения.
